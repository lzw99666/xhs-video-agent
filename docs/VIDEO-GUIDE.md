## 2. This machine's environment conventions (important, read first)

### 2.1 Use Git Bash for bash, not WSL

On Windows, typing `bash` may drop you into **WSL** by default (`C:\Windows\system32\bash.exe`); operating a mounted-disk project inside WSL is very slow and the environment is a different one.

Use the Git Bash that ships with **Git for Windows** (after installing, search "Git Bash" in the Start menu, or use `git-bash.exe`). It can call the native Windows node/npm directly.

**Fixed instruction for the AI assistant (state it once per video session)**:

> All bash scripts in this project that involve web-video-presentation are run with Git Bash; node/npm use the native Windows versions, never WSL.

### 2.2 Make WorkBuddy load a new skill

Externally copied skills are not picked up automatically. After installing / upgrading a skill:

1. Fully quit WorkBuddy (**including the system tray process**)
2. Reopen it, or start a new session in the project

### 2.3 Use a separate subdirectory per video

The scaffold script requires the target directory to be empty (it aborts if not), so **do not** create it at the project root. Recommended:

```
<repo-root>\videos\<video-short-name>\
├── article.md        # Original article
├── script.md         # Narration script (AI-generated)
├── outline.md        # Development plan (AI-generated)
└── presentation\     # Web project generated by the scaffold
```

### 2.4 Use the free edge-tts for TTS (no API key needed)

The skill's default TTS is the MiniMax CLI (mmx), **do not install it**. Use the officially reserved edge-tts provider (Microsoft Edge speech interface, free):

```powershell
pip install edge-tts
```

Verify after installing: `edge-tts --version`. Common Chinese voices:

- `zh-CN-YunxiNeural` (male, default)
- `zh-CN-XiaoxiaoNeural` (female)

If Git Bash says the `edge-tts` command is not found, make sure Python's `Scripts` directory (the `Scripts` under `python -m site --user-base`, or the `Scripts` under your Anaconda install) is on PATH, then reopen the terminal.

## 3. Standard workflow quick reference

```
Phase 0 Research (project-level addition, see WORKFLOW.md 3.1)
  The regular line / CS188 line first produce a facts.md research card (sources + key data + abstract concept → visual metaphor);
  no writing until the research is solid. The gh-daily line is exempt (fetch.py's topic card is the research layer).
  ▼
Phase 1 Content writing
  facts.md + original article → AI produces script.md (narration script) + outline.md (chapter/step plan
  + shot elements: transition method per step / visual focus movement / reading-protection duration)
  ▼
[Checkpoint 1 · hard stop] Align on 6 things at once:
  ① research card  ② script  ③ outline  ④ theme (1 of 23)  ⑤ assets  ⑥ development mode
  ▼
Phase 2 Web development
  Scaffold the project → chapter 1 must be done completely in one pass
  ▼
[Checkpoint 2 · hard stop] Human acceptance of chapter 1 (visuals/rhythm/AI feel), cannot be skipped
  ▼
  Chapters 2~N, three modes:
    A Chapter-by-chapter confirmation (default, most reliable)
    B Sequential development (no pauses, accept everything at the end, good for environments without subagents)
    C Subagent parallel (fastest, but style will vary between chapters)
  ▼
[Checkpoint 3 · hard stop] Should audio be synthesized?
  ▼
Phase 3 Audio synthesis (optional): extract-narrations → batch edge-tts synthesis → public/audio/
  ▼
Phase 4 Recording: ?auto=1 single continuous take
```

**What the four files are for (the AI's "external memory")**:

- `facts.md`: research card — source list, key data (with provenance), abstract concept → visual metaphor mapping. Required for the regular/CS188 lines, **no writing until the research is solid**; the gh-daily line is exempt (fetch.py's topic card is the research layer)
- `article.md`: raw material, **do not delete**; come back here to pull details when building screens
- `script.md`: the narration script, decides the rhythm (order cannot be changed)
- `outline.md`: the development plan, governs chapter splitting, screen content per step, information density and shot elements (transition method / visual focus movement / reading-protection duration), **does not prescribe the concrete animation implementation**

**Single source of truth**: `narrations.ts` in each chapter directory. Its array length = the chapter's step count = the audio file count. After changing the step count, also bump the STORAGE_KEY version in `src/hooks/useStepper.ts` (e.g. v4 → v5), otherwise the playback progress remembered by the browser will be misaligned.

**Beat table and style switching (see `WORKFLOW.md` 3.7 / 3.8)**:
- **Beat table (millisecond level)**: `script.md` separates beats with `---` (one beat = one step); after the script is final, produce `beats.json` (`step_id/chapter/start_ms/dur_ms/text`). Duration comes preferably from TTS measurements (`audio-segments.json` + `marks.json`); estimates must be labelled; chapter code must not hardcode milliseconds/seconds, audio alignment always reads `marks.json`
- **Switching style changes only the prompts**: the timeline / motion skeleton / step split stay fixed; changing only `src/styles/tokens.css` (theme tokens) and the chapter visual prompts re-skins the whole video (paper-cut / blueprint / miniature / pixel and so on); a style switch must not change the step count

## 4. Three recording modes (the pitfall hotspot, remember these)

| How you open it | Behavior |
|---|---|
| Open `localhost:5173` directly | **Manual (default): click / arrow keys advance, no audio plays** |
| Add `?audio=1` to the URL, or press `M` | Audio: audio plays automatically on entering a step, but **you still click manually** to advance |
| Add `?auto=1` to the URL | Auto: plays audio + advances automatically when it finishes, used for recording; the first time you must **press Space once** to start (bypassing the browser autoplay restriction) |

- There is a **hidden mode-switch button** in the top-right corner that appears only on mouse hover (deliberately hidden to keep the recording image clean); hovering at the bottom edge reveals the progress bar.
- Auto mode advances strictly on "audio finished + reading-protection time" (template default **1500ms**, since 2026-10-17; adjustable for the whole video with `?auto=1&trail=800`, and the recording script passes it through with the `TRAIL_MS` environment variable), with no fallback that waits for animations. **A step animation cut in half = that narration passage is too short**: go back to the chapter code and fix it — lengthen the narration / split the step / speed up the animation. Audio alignment is unaffected by trail: `build_master.py` places audio at the switch times measured in marks.json.
- Auto-mode recording needs no mouse clicking at all: full screen (F11) → start the recorder → press Space once → stop recording when it ends → trim the head and tail.

### Pitfall ①: the page clicks but there is no sound

After the first successful run the audio files were all there, but clicking the page produced no sound, and it took a long time to figure out. The reason: **it is Manual mode by default and by design does not play audio**, so it is not a bug. For recording use `?auto=1` directly, or press `M` to switch to Audio. The SKILL procedure says "the AI should proactively mention ?auto=1 after audio synthesis", but the AI did not do that at the time — so remember key operations like this yourself; do not count on the AI prompting every time.

## 5. Audio synthesis flow (free edge-tts route)

```bash
cd presentation
npm run extract-narrations     # scan all chapter narrations.ts → audio-segments.json
                               # eyeball the JSON first and confirm the text is correct
```

Then save the skill's built-in edge-tts snippet as a provider (the AI can do this for you):

- Snippet location: the "edge-tts" section of `skills\web-video-presentation\templates\scripts\tts-providers\README.md`
- Action: copy the snippet to `presentation\scripts\tts-providers\edge-tts.sh` (three-function contract: tts_check / tts_install_help / tts_synthesize; the snippet is complete and works as-is)
- Synthesis:

```bash
PRESENTATION_TTS=edge-tts npm run synthesize-audio
# specify a voice:
PRESENTATION_TTS=edge-tts PRESENTATION_TTS_VOICE=zh-CN-XiaoxiaoNeural npm run synthesize-audio
# incremental synthesis: already generated mp3 files are skipped automatically; add -- --force to redo after editing the text
```

### Pitfall ②: the AI asks you to install the MiniMax CLI

The AI follows the default flow and asks you to install `mmx` (the official MiniMax CLI, which needs an API key/quota). You do not need it — the skill's TTS is pluggable by design, and edge-tts is a free alternative prepared in the official docs; on Windows it runs directly from Git Bash.

### Pitfall ③: layout issues need many small adjustments

After all chapters are done there are small layout issues, and adjusting them through repeated conversation is slow. The skill's official principle is "feedback fixes in the smallest slice":

- Change only the smallest unit (locate the problem by rhythm/visuals/code layer); do not tell the AI to redo the whole chapter in one sentence
- But **batch the issues and raise them all at once**, do not go one question at a time — every conversation makes the AI reload the whole project context, which costs the most credits

## 6. Credit cost and a money-saving checklist

First real run (2026-10, the case "The 600ms After the Email Was Sent", completed as 7 chapters serially, without subagents):

- Actual cost **about 400 credits ≈ 15.2 CNY** (1000 credits / 38 CNY)
- Running it fully in parallel is estimated at under 300 credits
- Why serial costs more: for every chapter it develops, the AI reloads a thick `CHAPTER-CRAFT.md` (principles / decision tree / anti-AI-feel / checklist), so 7 chapters = 7 repeated loads

But serial is not wrong — without development experience, per-chapter human acceptance keeps rework inside a single chapter instead of sinking the whole thing; parallel saves credits but bets that the chapter-1 anchor is solid enough.

**Money-saving points (ordered by return)**:

1. **Confirm the 6 things at checkpoint 1 carefully, in one pass**, especially the research card, script and outline. Editing later is a chain of costs: script → narrations.ts → re-synthesize audio → STORAGE_KEY.
2. **Be harsh in the chapter-1 acceptance**: purple-pink gradients, rounded colored borders, fake illustrations, emoji, mindless entrance animations — kill all this "AI feel" in chapter 1, and later chapters will follow chapter 1's anchor.
3. Batch the revision notes and raise them once (see pitfall ③).
4. Only try mode C parallel once you are experienced (if WorkBuddy supports subagents); chapter 1 still has to be serial + human accepted.
5. Every chapter must have a CSS/SVG/Canvas visual demo, no pure text; a checklist list shows 1 item = 1 step, never all at once — watch the AI do this at kickoff, which is cheaper than redoing it.

## 7. Common commands quick reference

```bash
# Run in Git Bash; skills/ is where web-video-presentation is installed
# list the 23 themes
bash skills/web-video-presentation/scripts/scaffold.sh --list-themes

# scaffold (run one level above videos/<video-name>; the target directory must not exist or must be empty)
bash skills/web-video-presentation/scripts/scaffold.sh ./presentation --theme=blueprint
```

```bash
cd presentation
npm run dev                 # dev server (default 5173/5174)
npx tsc --noEmit            # type check, run once after each chapter
npm run extract-narrations  # extract narration text → audio-segments.json
PRESENTATION_TTS=edge-tts npm run synthesize-audio   # free audio synthesis
```

Recommended themes (technology-learning content): `blueprint` (engineering drawing style, good for architecture/teardown), `chalk-garden` (classroom explainer style), `terminal-green` (code demos), `forest-ink` (measured storytelling). Switching themes only requires overwriting one file, `src/styles/tokens.css`.
